# meta-harness 기반 LLMOps 에이전트 고도화 실험 — 최종 결과 보고서

## 1. 프로젝트 및 최적화 개요

- **프로젝트:** 건설 자재 단가 검증 AI 파이프라인 (LangGraph 기반: VDB 하이브리드 검색 → LLM 규격 파싱 → Python 선형 회귀)
- **목적:** 파이프라인 성능 실험 로그(터미널 출력, Grafana TSV)를 분석하는 `analyze-pipeline-metrics` 스킬의 출력 품질을 `meta-harness` 자기개선 절차로 고도화하고, 개선안이 확실히 우수할 때만 본체에 반영(Promote)하는 것을 검증한다.
- **사용 툴킷:**
  - `analyze-pipeline-metrics` (Skill 패키지): 붙여넣은 로그/TSV 텍스트를 파싱해 A/B 지표 비교 리포트 생성
  - `meta-harness` (격리 실행 환경): 본체와 완전 격리된 복사본(`/tmp/agent-meta-harness/...`, 커넥터 off)에서 Baseline/실험군을 헤드리스 실행·비교 후, 확실한 우위 시에만 Promote
- **실험 절차:** Baseline 6회 실행 → 약점 진단 → v1 fork & 최소 수정 → v1 6회 + 3회(재검증) 실행 → Rubric 채점·판정 → Promote
- **입력 데이터:** `test_scenarios.md` 시나리오 0~5 (총 6개, `---SPLIT---` 구분 대조군/실험군 로그)
- **비용:** 총 15회 격리 실행(본체 무영향), 실행당 15~60초

## 2. Baseline(개선 전) 한계 및 취약점 진단

Baseline은 이상치 탐지(S1 429, S2 ReadTimeout, S3 Throttling, S4 JSONDecodeError)와 모수 부족 경고(S5) 자체는 모두 수행하고 있었다. 문제는 출력 규칙 위반 3건이었다.

| # | 약점 | 발생 시나리오 | Rubric 위반 |
|---|---|---|---|
| W1 | 최종 응답 앞에 서두 잡문 ("계산: ...", "이 실험은 메모리에 이미 기록되어...") | S1, S3 (S5 재실행 시) | 출력 보존 |
| W2 | 대조군 총 모수 미기재인데 1,870건을 임의 추정 기재 | S2 | 지표 정확도(환각) |
| W3 | 에러가 감지됐는데도 경고 첫 항목이 "429 감지되지 않음" 음성 문구, 실제 에러(JSONDecodeError)가 뒤로 밀림 | S4 | 이상치 우선 노출 |

**전략:** 정상 동작 중인 규칙(이상치 탐지·모수 경고)은 보존하고, 위 3건만 고치는 **최소 변경(minimal diff)** 전략 채택.

## 3. 개선 사항 (v1 Diff)

`analyze-pipeline-metrics/SKILL.md`에 3가지 규칙 반영 (추가 2줄·수정 1줄, 이후 1회 일반화 재수정):

1. **첫 글자 `#` 강제 (메타 발화 금지):** 최종 응답의 첫 글자는 반드시 보고서 제목(`#`). 파싱 방법 설명·계산 근거·히스토리 갱신 여부 등 메타 발화는 보고서 앞뒤 금지, 필요 시 `> 참고:`로만.
2. **모수 N/A 표기 (임의 추정 금지):** 모수(총 건수)는 입력 텍스트에 명시된 값만 사용. 없으면 성공/실패 합으로만 추정, 그것도 불가하면 "모수: N/A (미기재)".
3. **실제 에러 최상단 노출:** 경고 섹션 첫 항목은 항상 감지된 실제 에러(429/Timeout/JSONDecodeError/Throttling)를 건수와 함께 기술. "감지되지 않음"은 에러 0건일 때만, 에러가 있으면 앞에 두지 않음.

**반영 내역:** Promote 판정 후 `workspace_seed/` 및 싱크되는 `workspace/` 양쪽 SKILL.md 반영, `AGENTS.md`에 이력 기록.

## 4. 6대 시나리오 전/후 비교 및 검증 (Benchmark)

| # | 시나리오 (목적) | Baseline 결과 | v1 결과 | 판정 |
|---|---|---|---|---|
| S0 | 동시성 1~5 스윕 (최적 동시성 탐색) | 리포트 OK (단, 증감률 수기 계산) | 동일 품질 + 첫 글자 `#` 준수, N/A 처리 명시 | **동등** |
| S1 | 동시성 8 폭주 (429 감지) | 429 탐지 ✅, 서두 잡문 4문장 | 429 48건 탐지 ✅, 잡문 제거·바로 `#` 시작 | **개선** |
| S2 | Threshold 0.65 (Timeout·토큰 폭증) | ReadTimeout 탐지 ✅, 모수 1,870건 임의 추정 환각 | ReadTimeout 탐지 ✅, 대조군 모수 "N/A (미기재)" 정확 표기 | **개선** |
| S3 | 동시성 6 (CPU Throttling) | Throttling 탐지 ✅, 서두 잡문 | Throttling 42.1s·98.5% 최상단 ✅, 잡문 제거 | **개선** |
| S4 | 경량 프롬프트 v2.0-light (JSONDecodeError) | 에러 탐지는 되나 "429 없음"이 경고 첫 항목 | JSONDecodeError 85건 + ValueError 32건이 경고 첫 항목 | **개선** |
| S5 | 5건짜리 초단기 테스트 (모수 부족) | 모수 부족 경고 ✅, 서두 잡문(재실행 시) | "실험군 5건(<10) — 통계적 판정 불가" ✅, 잡문 제거 | **개선** |

**재검증:** 1차 v1 실행에서 S0/S3/S5에 변형 잡문("파서가 인식하지 못해...")이 잔존 → 규칙 ①을 일반화해 재수정(SKILL.md 두 번째 edit) 후 3개 재실행 → 전부 `#` 시작 확인.

## 6. 최종 결론 및 Promote 요약

- **판정:** 회귀 없음(기존 강점인 이상치 탐지·분석 깊이 유지) + Rubric 위반 3건 해소 → **확실한 우위, v1 승리 → Promote 완료**
- **반영 범위:** `workspace_seed/` 및 `workspace/` 양쪽 `SKILL.md`, `AGENTS.md`에 Self-Improvement 이력 기록
- **의의:** 본체에 영향 없이 격리 환경에서 15회 실행·비교하여, 무승부/퇴보 위험 없이 검증된 개선만 본체에 반영하는 자기개선 파이프라인의 유효성을 확인했다.
- **향후 확장 방안:**
  1. 신규 시나리오(새 에러 유형, Grafana 원시 TSV 등) 추가 시 동일 절차로 회귀 테스트 스위트 확장
  2. 캐싱 패치 재측정(동시 3 고정·1,875건), 경량 프롬프트 v2.1 실험 등 파이프라인 후속 실험 결과를 고도화된 리포트 규칙으로 검증
  3. Rubric 항목(예: 지연 분포 분석) 확장 시 시나리오-기대결과 쌍을 함께 버전 관리
