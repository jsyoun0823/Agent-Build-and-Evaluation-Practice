# [최종 결과 보고서] meta-harness 기반 LLMOps 성능 분석 에이전트 자기개선 및 최적화

## 1. 프로젝트 및 최적화 개요

* **배경 및 목적:**
엔터프라이즈 AI 파이프라인(건설 자재 단가 검증 시스템)의 성능 분석을 수행하는 `analyze-pipeline-metrics` 에이전트의 실효성과 신뢰성을 검증하고, 자기개선(Self-Improvement) 루프를 통해 보고서 출력 품질, 이상치 탐지 우선순위, 환각(Hallucination) 방지 규칙을 고도화함.
* **사용 기술 및 프레임워크:**
* **Agent Skill:** 온디맨드 방식으로 실행 절차 및 가이드를 주입하는 `analyze-pipeline-metrics` 패키지 (`SKILL.md`, Python 기반 지표 연산기)
* **meta-harness:** 본체 환경에 영향을 주지 않고 `/tmp/agent-meta-harness/...` 격리 환경에서 A/B 테스트 및 조건부 본체 반영(Promote)을 수행하는 헤드리스 자기개선 엔진


* **평가 데이터셋:**
실제 단가 검증 파이프라인 성능 테스트 로그 기반 6대 벤치마크 시나리오 (동시성 스윕, HTTP 429, Timeout/토큰 폭증, CPU 스로틀링, JSONDecodeError, 모수 부족)

## 2. Baseline(개선 전)의 한계 및 취약점 진단

Baseline 상태에서 6개 시나리오를 헤드리스로 평가한 결과, 이상치 자체는 탐지하였으나 Rubric(평가 기준) 대비 3가지 핵심 약점(Weakness)이 식별되었습니다.

| 번호 | 약점 분류 | 발생 시나리오 | 세부 내용 및 Rubric 위반 사유 |
| --- | --- | --- | --- |
| **W1** | **리포트 출력 보존 위배 (서두 잡문 노출)** | S1, S3 | 최종 마크다운 리포트 이전에 `"계산: ..."`, `"이 실험은 메모리에 이미 기록되어..."`, `"파서가 인식하지 못해..."`와 같은 메타 발화가 출력되어 UI 렌더링 오염 및 구조적 일관성 훼손 |
| **W2** | **지표 정확도 위배 (모수 임의 추정 환각)** | S2 | 대조군 입력 로그에 총 모수가 명시되지 않았음에도 `1,870건`을 임의로 유추/기재하여 기획서 내 'No Hallucination' 원칙 위반 |
| **W3** | **이상치 우선 노출 위배 (경고 항목 전도)** | S4 | 심각한 파싱 에러(JSONDecodeError 85건, ValueError 32건)가 발생했음에도 경고 섹션 첫 머리에 `"429 감지되지 않음"`이라는 음성 문구가 먼저 노출되어 실무자의 빠른 상황 판단을 방해 |

## 3. 개선 사항 (v1 Diff)

에이전트의 추론 로직을 불필요하게 뒤흔들지 않고, 식별된 약점 3건을 칼같이 통제하기 위해 `SKILL.md`에 추가 2줄, 수정 1줄의 최소 변경 전략(Minimal Edit)을 적용했습니다.

```markdown
### [SKILL.md 변경 내역]
① 최종 응답의 첫 글자는 반드시 보고서 제목(`#`)이어야 한다. 파싱 방법 설명, 계산 근거, 
   히스토리 갱신 여부 등 메타 발화는 보고서 앞뒤 금지. 필요 시 `> 참고:`로만 작성.
② 모수(총 건수)는 입력 텍스트에 명시된 값만 사용. 없으면 성공/실패 합으로만 추정, 
   그것도 불가하면 "모수: N/A (미기재)"로 표기. 임의 추정 절대 금지.
③ 경고 섹션 첫 항목은 항상 감지된 실제 에러(429/timeout/JSONDecodeError/Throttling)를 
   건수와 함께 기술. "감지되지 않음"은 에러 0건일 때만 사용하며, 실제 에러가 있을 때는 앞에 두지 않음.

```

## 4. 6대 시나리오 전/후 비교 및 검증 (Benchmark Table)

| **S0** | 동시성 1~5 스윕<br>

<br>(스위트스팟 탐색) | - 리포트 및 분석 정상 출력<br>

<br>- 증감률 수기 연산 및 메타 발화 혼재 | - 동일한 심층 분석 및 최적점(3) 도출<br>

<br>- 첫 글자 `#` 출력 및 서두 메타 발화 완벽 제거 | **동등 (품질 유지)** |
| **S1** | 동시 8 폭주<br>

<br>(HTTP 429 TPM 초과) | - 429 48건 탐지 완료<br>

<br>- 서두에 4문장 분량의 잡문 노출 | - 429 48건 및 백오프 72건 최상단 노출<br>

<br>- 잡문 제거 후 즉시 `# A/B 파이프라인...` 시작 | **개선 (출력 보존)** |
| **S2** | Threshold 0.65 완화<br>

<br>(Timeout & 토큰 폭증) | - ReadTimeout 12건 탐지<br>

<br>- 대조군 모수를 **1,870건으로 임의 추정(환각)** | - ReadTimeout 12건 최상단 노출<br>

<br>- 대조군 모수 **`N/A (미기재)`** 정확 표기 (환각 제거) | **개선 (환각 제거)** |
| **S3** | 동시 6 + 인프라 포화<br>

<br>(CPU 스로틀링 98.5%) | - Throttling 42.1s 감지 성공<br>

<br>- 서두에 계산 과정 및 메모리 중복 잡문 출력 | - CPU Throttling 42.1s·98.5% 최우선 노출<br>

<br>- 잡문 완전 제거 후 표준 템플릿 준수 | **개선 (출력 보존)** |
| **S4** | Prompt v2.0-light<br>

<br>(JSON 파싱 포맷 파손) | - 에러는 탐지되었으나 `"429 없음"`이 경고 1번으로 출력되어 우선순위 왜곡 | - **`JSONDecodeError 85건 + ValueError 32건`**을 경고 최상단으로 즉시 직행 배치 | **개선 (우선순위 정상화)** |
| **S5** | 5건 초단기 테스트<br>

<br>(모수 부족 검증) | - 모수 부족 감지는 성공했으나 재실행 시 서두에 변형 잡문 발생 | - **`실험군 5건(<10) — 통계적 판정 불가`** 명시<br>

<br>- 서두/말미 잡문 없이 즉시 리포트 렌더링 | **개선 (출력 보존)** |

## 5. 평가 기준(Rubric) 달성도 평가

* **이상치 탐지 (Robustness): [100% 달성]**
S1(429 48건), S2(ReadTimeout 12건), S3(Throttling 42.1s), S4(JSONDecodeError 85건) 등 모든 시스템/인프라/모델단 오류를 건수와 함께 경고 최상단에 배치하도록 교정 완료.
* **제약 조건 준수 (Constraint Adherence): [100% 달성]**
S5에서 5건짜리 데이터에 대해 섣부른 결론을 내리지 않고 "모수 부족(<10)으로 인한 판정 불가 및 1,875건 재측정 권장" 가이드라인을 완벽히 제시.
* **리포트 출력 보존 (Consistency): [100% 달성]**
6/6 시나리오 전체에서 도구 실행이나 계산 근거에 따른 서두 메타 발화를 완전히 차단하고, 첫 글자 `#`으로 시작하는 단일 표준 마크다운 보고서 서식을 확립.
* **지표 정확도 (Accuracy & No Hallucination): [100% 달성]**
비정형 집계 데이터 수신 시 미제공 지표에 대해 임의 추정하던 취약점을 제거하고, `N/A (미기재)`로 정확히 격리하여 엔지니어링 신뢰도 확보.

## 6. 결론 및 본체 반영(Promote) 요약

* **A/B 평가 판정:**
총 15회의 격리 환경 헤드리스 실행 결과, 기존 Baseline의 강점(동시성 한계 분석, 트레이드오프 심층 진단)은 100% 보존하면서 식별된 약점 3건(W1, W2, W3)을 완전히 해소함.
* **최종 조치:**
회귀(Regression) 없는 명백한 성능 우위가 입증되어, `meta-harness` 엔진을 통해 `workspace_seed/` 및 `workspace/` 내의 `SKILL.md`에 수정 사항을 즉시 자동 반영(Promote) 완료하고 `AGENTS.md`에 작업 이력을 영구 기록함.
* **기대 효과:**
향후 건설 자재 단가 검증 AI 파이프라인 고도화 시, 로컬 콘솔 로그 및 Grafana 텍스트 입력만으로도 환각 없는 정확한 지표 비교와 실무 즉시 적용 가능한 파라미터 튜닝 제안을 일관되게 제공받을 수 있음.
