# analyze_pipeline_metrics — 파이프라인 성능 비교 분석 (텍스트 입력 전용)

> ⚠️ 사내망 보안 정책상 **파일 업로드(CSV/Log)는 완전히 차단**되어 있다.
> 모든 데이터는 사용자가 채팅창에 붙여넣은 원문 텍스트로 들어온다.
> **file_reader 등 파일 읽기 도구/MCP를 호출하려 시도하지 않는다.**

## [Trigger]
사용자가 터미널 콘솔 출력 텍스트나 Grafana의 TSV/CSV 형식 문자열을 프롬프트에 붙여넣으며
"성능 비교해 줘", "최적화 분석해 줘", "실험군/대조군 비교해 줘"라고 요청할 때 즉시 동작.

## [입력 데이터 형태]
1. **터미널 표준 출력 로그**: `latency=1234ms tokens=2450 vdb_score=0.87 status=success` 같은 key=value 로그.
2. **Grafana Inspect Data 복사본**: 탭(`\t`) 구분 TSV 또는 쉼표(`,`) 구분 CSV 문자열 (첫 줄이 헤더인 경우가 많음).
3. **설정값 메모**: "병렬 4로 테스트함" 같은 자연어 메모 — 파라미터 컨텍스트로만 활용.

## [Tools]
아래 스크립트는 모두 Python 표준 라이브러리만 사용하며, 원문은 파일이 아니라 `--text` 또는 stdin으로 전달한다.

1. `scripts/parse_inputs.py`: 콘솔 로그 또는 Grafana TSV/CSV를 정규화 JSON으로 변환.
2. `scripts/calculate_metrics.py`: 대조군과 실험군의 집계 지표 및 증감률을 계산.
3. `scripts/detect_anomalies.py`: 에러, 지연 스파이크, 트레이드오프, 모수 부족을 검사.

각 스크립트는 JSON을 stdout으로 출력한다. 원문이나 중간 결과를 파일로 저장하지 말고, 인자 또는 파이프(stdin)로 전달한다.

## [Execution Procedure]
1. **데이터 추출 및 연산:** 대조군과 실험군 원문을 각각 `scripts/parse_inputs.py`에 전달하고, 파싱 JSON을 `scripts/calculate_metrics.py`와 `scripts/detect_anomalies.py`에 전달한다.
   - TSV/CSV 헤더 및 콘솔 로그 패턴은 위 입력 규칙대로 파싱한다. 원문에 없는 값은 채우지 않는다.
   - 일부 행을 파싱하지 못하면 건너뛰고 성공/스킵 건수를 기록한다. 지표가 누락된 경우 N/A로 둔다.
   - 전체 입력에서 지표를 인식하지 못하면 인식된 패턴과 함께 예시 로그 한 줄을 요청하고 분석을 멈춘다.
   - 대조군 입력이 없으면 `/AGENTS.md`의 [Recent Experiment History]에서 가장 최근 성공적 실험을 사용한다. 비교 가능한 대조군이 없으면 증감률을 만들지 말고 사용자에게 대조군을 요청한다.
   - 평균 지연, P95 지연, 평균/총 토큰, 성공률, A/B 증감률과 이상치 검사 결과를 스크립트 JSON에서 확인한다. 기준값 0 또는 결측의 증감률은 N/A로 둔다.
2. **JSON 검토 및 히스토리 갱신:** 결과 JSON을 검토하고, 분석 결과(날짜, 실험명, 파라미터, 핵심 지표, 성공 여부)를 `/AGENTS.md`의 [Recent Experiment History]에 도구 호출로 추가한다. 429/504, timeout, 지연 스파이크, 트레이드오프 및 모수 부족을 보고서에 반영할 수 있도록 결과를 보존한다.
   - 이 단계에서 모든 스크립트 실행과 파일 읽기/수정 도구 호출을 끝낸다. 히스토리 갱신을 완료하지 못했다면 완료했다고 쓰지 말고 보고서에 상태를 밝힌다.
3. **최종 응답에 전체 보고서 출력:** 모든 도구 작업이 끝난 뒤 `references/report_format.md` 형식의 상세 보고서 전체를 최종 응답 하나에 작성한다. 비교표, 경고, 주요 분석, 권장 설정 및 다음 단계를 빠짐없이 포함한다.
   - 보고서 초안이나 일부 내용을 도구 호출 전/중간 메시지로 따로 보내지 않는다. 프론트엔드가 마지막 AI 턴만 표시하더라도 보고서 전체가 보이도록, 마지막 응답 자체를 보고서로 구성한다.
   - **최종 응답의 첫 글자는 반드시 보고서 제목(`#`)이어야 한다.** 파싱 방법 설명("파서가 인식하지 못해", "스크립트가 ... 수동 계산"), 계산 근거 나열("계산: ..."), 히스토리 갱신 여부("이 실험은 메모리에 이미 기록되어", "중복 갱신은 생략") 등 **보고서가 아닌 모든 메타 발화·메모·사전 설명을 보고서 앞뒤에 붙이지 않는다.** 이런 내용이 필요하면 보고서 내부의 주석(`> 참고:`)으로만 쓴다. 서두에 잡문이 한 문장이라도 있으면 출력이 깨진 것으로 간주하고 보고서만 다시 출력한다.
   - 보고서 뒤에 짧은 요약이나 마무리 문장을 별도 응답으로 보내지 말고, 최종 응답 이후 추가 도구 호출도 하지 않는다.
   - **모수(총 건수)는 입력 텍스트에 명시된 값만 사용한다.** 대조군·실험군 중 총 건수가 로그에 없으면 성공/실패 건수 합으로만 추정하고, 그것도 불가하면 "모수: N/A (미기재)"로 둔다. 성공 건수만 있을 때 임의의 총 건수를 추정해 기재하지 않는다.
   - 계산 JSON에 없는 수치나 원인을 추정하지 않는다. **경고 섹션의 첫 번째 항목은 항상 감지된 실제 에러(429, timeout, JSONDecodeError, ValueError, CPU Throttling 등)를 건수와 함께 기술한다.** "429/timeout 감지되지 않음" 같은 음성 결과는 감지된 에러가 하나도 없을 때만 쓴다. 감지된 에러가 있으면 음성 문구를 앞에 두지 않는다. 10건 미만은 모수 부족으로 표시한다.

## [금지 사항]
- 입력된 텍스트에 없는 수치를 임의로 유추/창조하지 않는다.
- 파일을 열거나 파일 경로를 요구하지 않는다 (텍스트 붙여넣기만 사용).
- 사용자의 파이프라인 코드나 설정을 직접 수정하지 않는다 (분석·제안만).

## [Reference Material]
- `references/report_format.md`: A/B 비교 리포트의 표 및 글머리 양식.
- `scripts/parse_inputs.py`: stdin 또는 `--text` 입력을 집계 JSON으로 파싱.
- `scripts/calculate_metrics.py`: 파싱 JSON 두 개를 받아 비교 지표 JSON을 출력.
- `scripts/detect_anomalies.py`: 비교 지표 JSON을 받아 경고 JSON을 출력.
